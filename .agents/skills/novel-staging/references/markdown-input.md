# 从 Director 文档准备站位工具输入

仅在需要脚本或交互报告时提取。保留原剧本、场号和人物身份；不要要求用户改写成另一套项目格式。

## 提取字段

读取目标集的剧本和视觉设定，将事实抄入临时 JSON。下例只演示脚本所需结构：

```json
{
  "source": "剧集/EP001/剧本.md；当前版本或修改时间",
  "lang": "zh",
  "episodes": [{
    "ep": 1,
    "scenes": [{
      "sourceSceneId": "EP001-SC001",
      "sceneId": "LOC-HALL",
      "characters": ["CHAR-A", "CHAR-B"],
      "lighting": "夜；门侧暖灯"
    }]
  }]
}
```

`sceneId` 是地点 ID，不是场号。同集 `scenes` 顺序对应脚本的场序；包含后来才进场的人，开场是否在场由 `places[].present` 表示。若只选部分场次，保留原集完整场序骨架或显式记录输出场序到 `sourceSceneId` 的映射，不能把重新编号当原场号。`sourceSceneId` 是供回填核对的附加字段，seed 不会把它复制到输出。

可选地点映射：

```json
{"scenes": [{"id": "LOC-HALL", "name": "门厅"}]}
```

可选姓名映射：

```json
{"characters": [{"id": "CHAR-A", "name": "甲"}, {"id": "CHAR-B", "name": "乙"}]}
```

只有原文已确定的事实才能进入上述字段。缺少地点、出场人物或场号关系时先核对对应段落，不让 seed 的空数组或默认值掩盖遗漏。场景具体动作仍从原剧本读取，不从 seed 猜测。

## 执行与回填

1. 将这些输入放在作品已有临时工作目录或系统临时目录；记下来源版本与场号映射。
2. 按 SKILL.md 的 seed 命令生成骨架，核对目标集、场次、地点和出场人物没有丢失。
3. 按真实图或明确标记的空间草案补家具与站位，执行 validate；HTML 检查通过不等于画面关系已经验收。
4. 采用后把开场走位句写回相应分镜；保留 HTML/JSON 作为工具记录。修改正式走位以分镜为准，需要继续拖动时重新同步输入，不维护两份互相竞争的创作事实。
