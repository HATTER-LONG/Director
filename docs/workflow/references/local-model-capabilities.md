# 当前本地图像、视频与音频能力

本页记录 2026-11-06 核对的部署能力，依据 Toonflow `listMediaProviders`、`data/providers/comfyH3.ts`、`data/providers/cpa.ts` 与 ComfyUI `object_info`。它是当前适配器的能力快照，不是模型全部能力或出片质量保证。供应商、工作流或版本变化时重查；同一会话未变的参数可复用，提交前仍核对当前节点和实际输入。

后续增量核对日期见各节。音频部分于 2026-11-09 对照本地适配器、节点源码、实时 `object_info` 与作品运行记录补入；本次文档核对未重新提交生成。

## 参考优先

默认用完整的人物、造型、场景和道具参考，加提示词说明取景、动作与终点。完整是足够交代本镜所需事实：人物全身与脸部细节、服装和持物，场景布局与必要反打，道具形制与状态；按镜头需要组合，不规定每镜都挂齐全部资产。不把人物参考摆成某一首尾姿态，不为锁帧删掉理解动作所需的信息。

参考图可以保持原画幅。多视图属于同一人物时明确绑定同一主体；标注与排版不进入成片。细节太小或多视图引起歧义时补清晰视图，不默认把完整参考裁成视频画框。起点和终点首先是分镜中的状态描述，关键帧图按需准备。

## GPT Image 2.6：当前 CPA 入口

- 供应商 `cpa`；实际模型 ID 为 `gpt-image-2.6`，另有 `gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`。沿用用户选定 ID，不因名字相近自动替换。
- 当前仅开放 `1K`，比例为 `1:1`、`3:2`、`2:3`；每次 `n=1`。适配器的请求尺寸映射为 `1024×1024`、`1536×1024`、`1024×1536`，但实际回收文件可能不同；入库时读取文件宽高，不能把请求值当作已实测尺寸。不能把通用 API 的其他尺寸、透明背景或种子能力直接写成此节点可用参数。
- 无图走生成；有图走编辑，按实际顺序用自然语言说明每张图控制的身份、空间、材质等范围。H3 的 `<Picture N>` 不是此图片接口的参考语法。编辑说明“改什么、保持什么”；mask 只有节点确实暴露且已接入时才算有效。
- 质量选项为 `auto/low/medium/high`，输出为 `png/jpeg/webp`，以节点实际暴露字段为准。候选探索和最终资产可分别选合适质量，不强制每次最高质量。
- 人物和空间参考无需裁成 9:16。只有交付确需 9:16 构图帧时，先按 2:3 出图并预留取景余量，再按实际画面裁切；若实测为 1024×1536，居中 9:16 窗口为 864×1536，两侧各裁 80 px；其他尺寸重新计算。先检查头、手、道具和文字，不拉伸；裁不下就调整取景或编辑原图。

官方图像接口背景见 [Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)；实际可提交范围以上述部署为准。

## H3：当前 comfyH3 入口

- `h3-quick` 与 `h3-enhanced` 使用 `MiniMaxH3ReferenceToVideo`。UI 的 `singleImage` 也是参考输入；不支持 `firstFrame/lastFrame` 端口，不能宣称严格 I2VA/FL2VA 或用参考图强制首尾帧对齐。有参考时按 Ref2VA 编译；无参考的 text 任务按文生格式编译。
- 最多 9 张图片、3 段视频、3 段独立音频。`<Picture N>`、`<Video N>`、`<Audio N>` 各类型分别从 1 编号，并与实际挂载顺序一致。2026-11-08 起，快速和增强均支持 Toonflow `@参考` / `{{ref N}}`，按真实引用顺序转换为上述 H3 标签；手写标签继续可用。素材引用编号与 `<Subject N>`、说话人编号分别维护。
- 完整参考说明什么应保持，动作正文说明怎么变化。构图、朝向和动作终点是生成目标，不能写成已被端口锁定的事实。不要为凑满槽位加入冲突造型或多余视图。
- 目标时长为整数 2–15 秒、24 fps，帧数向上对齐到 `17n+5`。设 `N = 24 × 目标秒数`，实际帧数为 `N + ((5-N) mod 17)`（余数取 0–16）。例如 5 秒为 124 帧，约 5.167 秒；15 秒为 362 帧，约 15.083 秒。剪辑镜长、提交目标秒数、实测素材时长分别记录；不为取整改故事节奏。
- 分辨率在 Toonflow H3 节点中手动输入，范围 `0.4–2.0MP`，精度 `0.1MP`；快速和增强共用此范围。按总像素量与画幅计算宽高，并取 32 的倍数；不是固定 720p 或 1080p。此项于 2026-11-08 更新，已通过节点类型检查、构建和 ComfyUI 原生参数校验。2026-11-09 的 `h3-quick`、`1.0MP`、`9:16` 图片参考任务已完成请求 7 秒和 10 秒的真实生成，实测均为 `768×1376`；其他档位与最长时长的显存上限仍需实测。实际尺寸和片长用媒体文件核实。
- `generateAudio=false` 不连接最终输出音轨，不代表省去联合采样。不要据此保证提速。视频参考的音轨目前没有接入图；需声音参考时单独提取、挂载并说明用途，或后期保留原音轨。

### Pika Flex：新增的 `pika-h3-flex` 入口

2026-11-08 已接入同一 `comfyH3` 供应商。该配置使用「H3-Pika-全参考-显存优化」的单采样图、Pika Flex LoRA=1、LCM 和原 6 个 sigma 区间；TAE 预览固定启用。

- 「UNet 模型」下拉框支持本地原版 MiniMax H3 Ref2VA INT8（默认）和 Cobijada H3 Hybrid INT8，仅替换 UNet 权重。当前文件分别为 `minimax_h3_ref2va_pruned_int8_convrot.safetensors` 与 `Cobijada_H3_Hybrid_Uncensored_pruned_hybrid_int8_convrot_pruned.safetensors`，均位于 `diffusion_models/minimax-h3/`。不能据此保证其他权重或量化格式也兼容。
- 三个独立开关默认为 H3 Memory Opt 开、低显存关、采样后释放模型关。H3 Memory 与低显存同时关闭时，直通 Pika LoRA 后的原始模型，不添加 H3/KJ 采样显存补丁；H3 关、低显存开时才启用 KJ 注意力头 8 组与前馈 8 块/1024。H3 开启时，低显存开关选择 4096/Standard 或 1024/Lower VRAM。采样后释放独立控制正式音画解码前的卸载与缓存清理。
- 全关恢复的是采样显存路径，TAE 预览与扩展参考仍保留；它不重置 UNet、种子、提示词、素材和输出设置，也不关闭 ComfyUI 自身的量化或显存调度。全关新路径已通过原生参数及分支校验，尚未重新出片比较。
- 最多 9 图、3 视频、3 独立音频；支持 Toonflow `@参考` / `{{ref N}}` 映射，也可手写 `<Picture N>`、`<Video N>`、`<Audio N>`。各媒体独立编号，引用转换与上方快速、增强共用实现。
- 视频使用原文件经 `LoadVideo → GetVideoComponents` 输入，不额外裁切、缩放或重采样；H3 节点自身的条件编码仍按其实现处理。视频音轨不自动接入，声音参考使用独立音频。下文快速/增强的「24fps、前48帧」读取规则不能直接套到 Pika。
- 分辨率输入范围 `0.4–2.0MP`、步长 `0.1MP`；画幅、2–15 秒目标时长、24fps、`17n+5` 帧对齐、种子和输出声音选项沿用上方约定。

原版 UNet + H3 Memory 默认组合，以及 Cobijada + KJ 低显存 + 采样后释放组合，均已完成带图片、独立音频参考的真实生成和 Toonflow 回收；引用映射、TAE 预览和采样后释放已观察到实际效果。视频参考目前仅完成节点参数校验，未进行出片验证；这些检查不代表画质、声线或全部开关组合已验收。具体镜号、任务、参考和输出留在对应作品的接入验证记录。

分辨率选择、可选的低分辨率试片、串行迭代和交付复核见 [生成规格与可选试片](../08-toonflow-generation.md#生成规格与可选试片)。

## IndexTTS 2.5：本地参考音频配音

- Toonflow 供应商 `comfyIndexTts25`，模型 `index-tts-2.5-local`；实际配置见工作机 `toonflow/data/providers/comfyIndexTts25.ts`。输入恰好一段参考音频，不接图片；提示框填写要说的文本，情绪提示单独填写。当前适配器将 `en` 映射为 `EN`，其余映射为 `ZH`，不能据底层节点的语言列表宣称 Toonflow 已打通其他语言。
- 已接入的 ComfyUI 链为 `LoadAudio → LocalIndexTTS25 → LocalSaveAudioWAV`。服务校验参考音频为 0.2–30 秒，适配器限制文件不超过 20 MiB；文本为 1–2000 字符。支持种子、时长系数、可选情绪文本与生成后卸载。实际节点参数提交前回读。
- 情绪字段沿 `emotionText → emotion_text → use_emo_text/emo_text` 传入；引擎的文本情绪功能要求加载 QwenEmotion。引擎还提供 `emo_audio_prompt`、`emo_vector`、`emo_alpha` 和 `interval_silence`，但当前 `LocalIndexTTS25` 与 Toonflow 适配器未暴露这些控制，不能据引擎 README 宣称画布节点已支持。Toonflow UI、供应商与节点 MCP 的可配置字段也要分别核对；MCP 没有某字段时，不假称已设置，可在已有授权内通过已验证的同一底层链提交并把结果与参数回收到原画布。
- 本地 2.5 引擎接受 `<字|拼音声调>`，例如 `银<行|HANG2>`、`<行|XING2>走`、`还<得|DEI3>去`。依据为安装版本的 README、`indextts/utils/front.py` 与 `infer_v2_5.py`；这些是格式示例，不是本次已听审的语音样本。先核对目标读音与词表，再作短句对照。旧版的裸拼音写法不与新格式混用，标注只留在合成输入中。
- `durationFactor` 映射到节点 `duration_factor`，范围 0.5–2.0，界面步长 0.05；小于 1 倾向缩短时长，不能当成精确播放倍率或固定每秒字数。正常基准显式传 `1.0`。**当前默认值有差异**：Toonflow 新节点界面为 1.0，适配器缺参值与 ComfyUI 节点默认值仍为 0.8；旧节点和旧工作流也可能带旧值，必须核对实际请求，不能假定界面默认已同步到底层。
- 引擎原生输出 22050 Hz；适配器支持 WAV/MP3，缺省导出 24000 Hz，采样率可选 8000、16000、22050、24000、44100、48000 Hz。记录回收文件的实际规格，采样率转换不等于语速调整。
- 模型目录为工作机 `/home/layton/WorkSpace/ComfyUI-clean-data/models/IndexTTS-2.5`，官方引擎在 `/home/layton/WorkSpace/tools/opensource/indexTts25` 的独立 Python 环境。ComfyUI 节点通过 `indexTts25Local` 服务调用，首次执行可按需启动服务并惰性加载模型；不为复用工作流重复安装或改写 ComfyUI 的依赖环境。
- 本地服务监听 `127.0.0.1:8190`，`GET /health` 返回 `model_loaded` 与 `busy`，`POST /synthesize` 生成，`POST /unload` 卸载；并发请求被拒绝，按条串行。H3 与 TTS 共用单卡时分时使用，确认任务结束再切换；ComfyUI 清理缓存不会自动卸载独立服务中的 TTS 模型。

已有作品记录验证了从 Toonflow 提交、服务按需启动、WAV 回收及独立卸载；这不代表任意句子、情绪或语言已通过听审。发音控制按安装版本实际支持的格式填写；语速、读音和字幕的处理见 [配音与时间对齐](voice-and-timing.md#语速只从明确的基准调整)。

### TTS 与 H3 切换时释放缓存

2026-11-09 在本机核对：H3 结束后，ComfyUI 仍可能保留大量 CPU 内存与显存；IndexTTS 即使返回 `model_loaded=false`，独立 Python 进程也可能保留 CUDA 上下文或交换出去的运行内存。以进程、可用内存和显存的实测变化判断，不能把“任务完成”或“卸载请求成功”直接当作已释放。

1. **先结束当前批次。** 检查 ComfyUI `/queue` 的运行项和等待项，以及 TTS `/health` 的 `busy`。保存任务 ID 与已生成文件，停止本批次的自动提交脚本，确认没有下一条任务正在进入。不要在活动推理中清缓存，也不要用全局中断替代缓存清理。
2. **H3 转 TTS，或 H3 批次完成：** 队列空闲后向 ComfyUI `POST /free`，提交 `{"unload_models":true,"free_memory":true}`。当前核心会卸载模型、重置执行缓存并做垃圾回收；等处理完成，再检查实际进程 RSS、系统可用内存和 GPU 占用。
3. **TTS 转 H3：** 确认 `busy=false` 后向独立 TTS 服务 `POST /unload`，再读 `/health` 确认模型已卸载。ComfyUI 的 `/free` 不会代替这一步。若短期不再配音、模型已卸载但独立进程仍有明显残留占用，可以在授权范围内核对其可执行文件和 worker 路径后，正常终止这个空闲子进程；当前节点下次使用会按需启动。不要按进程名批量结束 Python。
4. **再启动下一类任务。** 连续同类镜头可以复用模型，不要求每镜卸载。显存占用和内存可用量仍不足时再定位具体持有者；不通过删除模型、原始素材、系统缓存文件或强制清空交换空间来代替进程清理。

释放后交换空间不一定立即归零。已退出、RSS 为零的僵尸进程也不再占模型内存；不用为消除列表项而中断仍有工作的父服务。具体 PID、前后数值、任务和操作结果写进作品制作记录，本页只维护切换方法。

## 两段视频怎么衔接

默认在分镜时设计切镜：前段的可剪出点与后段第一镜共同决定观感。前段人物中景收尾，后段可从对手反应、道具细节、不同景别或不同角度介入；仍须保持视线、轴线、持物和动作阶段。后段正文直接写切后第一镜的构图，不把“跨文件切镜”误写成生成转场特效。具体设计见 [分镜与镜序](../06-storyboard.md#跨生成段的剪辑接口)。

确需同一个人接着完成同一动作时，当前快速／增强路线使用上一段采用切点之前的最后 **22 帧**作为独立视频参考。以下读取与截取约定针对这两个适配器；Pika 或其他入口按自身实现核对，不直接套用前 48 帧限制：

1. 检查实际 take，选定可用切点，按解码帧准确截取截至该点的 22 帧；不足 22 帧时如实报告，不重复帧伪装。若采用整段结尾，就是文件最后 22 帧。
2. 当前 H3 输出 24 fps，22 帧约 0.917 秒。另存片段，保留原片，记录来源与帧范围。可用 FFmpeg 的 `trim=start_frame=S:end_frame=E,setpts=PTS-STARTPTS`（E 不含，E-S=22）并重新编码；不用可能偏到关键帧的流复制裁切。不同帧率来源需核对重采样后的实际输入，不能把 22 帧直接写成固定秒数。
3. 适配器会重采样到 24 fps，先载入视频开头，再只取前 48 帧，H3 条件按 `17n+5` 帧处理；22 帧可完整进入条件。因此挂裁好的尾部片段，不能挂整段原片期待它自动读结尾。
4. 把它绑定为 `<Video N>`，提示词交代“从这段参考末尾状态继续”，并写清人物、视线、持物手、接触位置、动作方向、速度和接下来的变化；不要重新演参考里的动作。完整人物与场景图仍按需保留，不强制再加尾帧图片。
5. 参考只引导连续性，不保证姿态或像素完全一致。出片后对照两侧动作与声音，优先用可用区间、切点或声音桥缓解差异；做不到已定连续动作才返工。

## 超时、停止和恢复

记录 Toonflow 的 requestId 与 ComfyUI prompt_id/taskId。超时先查原队列、历史和已有输出；适配器能按已有 ID 恢复查询，状态不明时不重新提交。服务已完成但画布未收回时先收回原产物。

前端重连或刷新后，重新读取 `getAppState`，定位原项目、画布和节点，再对照任务记录与输出文件。节点回到空闲状态不等于原任务失败，不能据此直接补跑。

Toonflow 的停止可能只停止等待，ComfyUI 仍会运行。收到停止要求后核对原任务在队列中的状态；只有确认目标是该任务时才取消。全局 interrupt 可能影响其他任务，不能当作按 ID 取消。记录最后状态，避免紧接着重投造成重复任务。
