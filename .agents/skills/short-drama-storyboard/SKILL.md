# 短剧分镜与冻结关键帧

把剧本和视觉事实转成有镜头职责、空间连续性和可冻结起点的 `剧集/<EP>/分镜.md`。
五文档项目每镜使用二级标题 `## SHOT-...`；已有 Toonflow 文档沿用原结构。先写开镜构图和起止状态；需要专门构图图时才用 `### 冻结关键帧提示词`，需要终态图时才用 `### 收尾关键帧提示词`，两者都不是必备图片。

## 快速开始

```text
用 $short-drama-storyboard 完成 EP001 的正式分镜、跨段切镜和参考清单
```

## 入口

当前剧本加必要视觉事实即可直接进入。资产图片提示词与分镜是兄弟分支，不互相等待。只有关键场次
真的存在多个成立导演方案时，才在上下文比较覆盖方案；普通场次直接设计。

创作者可读说明跟随项目语言；冻结关键帧的可复制正文跟随
`short-drama.json#/format/prompt_language`。没有 `short-drama.json` 时正文默认使用 `en`。
分配镜头前核对已选入口的实际时长范围，区分剪辑镜长与生成片长。已有配置项目可读取 `short-drama.json#/creator_authority/production_profile/choices/native_duration_seconds`；未配置时从制作记录或实际部署核对，不要求补配置。目标模型未定时先按叙事节奏设计，不猜供应商限制。
已有节奏档案时读取 `short-drama.json#/creator_authority/rhythm_profile`：`status` 为 `accepted` 时，镜长按
[镜长从哪来](references/shot-craft.md#镜长从哪来-sht-28) 由声音事件与 `target_avg_shot_seconds` 推出，
全集近景类镜头占比不低于 `close_shot_share_min`；档案缺失或未接受时不核对这些数值。

开镜画面确定后，再按画面中的可见内容填写视觉依据、图片提示词项和输入参考图，
避免只按镜头意图列资产而漏掉实际入画的人物或物件。

用户没有手工点名参考图，不等于选择文生视频。先根据本镜可见人物、地点、关键道具与
起始构图判断一致性需求，再检查项目中已有的真实图片。只有当前可读、内容与用途可核对的图片才能自动绑定；
文件名像某个角色但内容未核对时，仍视为未准备好。

项目里没有所需图片时，先列挂图计划并完成不依赖实图的分镜。用户本轮已授权补素材时转素材阶段完成；只写文稿时不自动生成，也不默认要求用户手工出图。使用五文档解析器时按 [交接格式](../short-drama/references/creator-documents.md) 记录 REF/PLAN 与缺口，提交前仍须核对真实输入。

开始分镜前读取当前剧本和最新用户修订；文件未同步时先标明差异并更新授权范围内的来源，不能让旧文件覆盖用户的新要求。

## 工作流

1. 确认每场动作、对白、声音、画面文字和转折由哪些镜头承载，再对照已核实的生成时长范围；未选模型时不阻断分镜。
2. 确定观众何时知道什么、对齐谁、空间如何揭示、转折落在哪个可见动作。
   剧本或 Brief 用“前半段 / 后半段 / 前三分之一 / 最后 N 秒”等相对时间限定首次出现、释放或禁止时，
   先用已接受集长换成明确时间边界再分镜；例如 60 秒作品的“后半段首次出现”不得早于 30 秒。
3. 每镜写清唯一职责、来源、时长、景别/机位、运镜、起点、唯一主要动作、终点和声音；用
   `起点 → 唯一动作 → 终点` 直接说明人物、双手与持物怎样完成本镜状态转换。来源和参考在第 6 步回填。
   数一下这一镜要观众看清的事，按镜长判断每件有没有足够的时间被看清；放不下时先删、合并或拆镜，见 [短镜头的动作量](references/shot-craft.md#短镜头的动作量-sht-03)：动作过多可能被遗漏、合并或压缩；取舍后仍须用样片核验。
   「运镜」按本镜目的逐镜选，写行为和理由，固定也写理由，见 [运镜逐镜选](references/shot-craft.md#运镜逐镜选-sht-04)。
   有对白、VO 或 OS 时，先按原文和人物说话方式估算完整发声时间，再安排不能重叠的动作、停顿与
   末尾反应；把估时依据简写在本镜「声音」里。具体做法见 [对白估时](references/shot-craft.md#对白估时)。
   对白场先按 [对白覆盖默认](references/shot-craft.md#对白场怎么切-sht-29) 放切点；镜长不按剧本字数折算。
4. 一场戏拍成多镜时，先在《分镜.md》开头写这场的「场景站位」：固定锚点、各人相对锚点与彼此的位置、轴线与 working side、哪一镜改变站位。再逐镜锁定朝向、位置、视线、持物、出入口和必要状态，与「场景站位」一致；起点、终点里的位置写锚点和人物关系，视线写看向谁或什么；冻结关键帧再把它翻成本镜机位下的前后景、朝向、中间隔着什么和画面左右，见 [站位先写锚点和关系](references/blocking-playbooks.md#站位先写锚点和关系)。上游已有会限制动作空间的持续关系时，把关系投影进本镜起点与终点。
5. 按需写关键帧；写起始关键帧时只投影镜头起点；删除终点才出现的文字、动作、姿态或道具状态。
   镜头的职责落在收尾那一下时，另写 `### 收尾关键帧提示词` 投影**终点**——同一格画面的
   另一端，规则完全对称：删除起点才有、终点已经不在的东西。它是可选的，写法与取舍见
   [首尾成对](references/shot-craft.md#首尾成对)。
6. 镜头画面确定后，从可见内容回填视觉依据，关联已有图片提示词和实际参考。先查采用素材，未核对内容的文件不能自动绑定；缺口按下方参考规则记录，不伪造条目或文件。
7. 对照相邻镜头核对视线、持物、轴线、声音与动作阶段，完成当前请求的全部场次，再检查引用和交接。

## 镜头要求

- 每镜有明确职责、剧本来源、可见起止状态和合理时长。来源应能定位到真实场次及本镜承担的动作或声音，不能拿画外人物声明代替动作落实。
- 请求范围内的剧本场次都要有镜头承载；决定不拍的场次在分镜说明原因，让下游能区分有意省略与遗漏。使用检查器时按交接格式记录来源与未拍场次。

- 剪辑镜长按叙事需要定，生成目标秒数与实际素材片长另记。短镜可以生成带余量素材后裁用，或在已授权范围按因果镜序打包；不能为模型最短时长拉长剧情。H3 默认不要求每切一张关键帧，超过单次上限时按可闭合动作拆段。
- 跨段先设计切镜：前段人物中景收尾，后段用反应、细节或改变取景介入，保持轴线、持物和动作阶段。必须同一人连续动作时，按本地流程准备前段采用切点前的视频参考，详见 [剪辑接口](../../../docs/workflow/06-storyboard.md#跨生成段的剪辑接口)。不默认同场所有镜头逐段接力。
- 「唯一动作」写从本镜起点到终点的那条可见状态链；涉及交接、换手、放置或取回时，把接触者、
  接触方式和物件落点写在同一链里，不能让合法终点之间靠镜外瞬移衔接。
- 切镜必须带来信息、权力、情绪、空间或节奏变化；同义重复镜头删掉。
- 相对时间词约束的是事件首次可见或可听的时刻，不因前置动作已经完成就提前释放；分镜时间轴直接
  写出该边界，不把“稍后”“交接后”等叙事顺序当成数值时间的替代。
- 同一动作不跨镜重复发生，峰值处声明过的[冲击重复](references/shot-craft.md#动作落实表)除外；终点应能成为下一镜可信起点。
- 关键信息的可读性优先于装饰性运镜，竖屏构图优先保证主体和反应可见。
- 复杂群戏先在「场景站位」里锁空间锚点、人物位置和轴线，再决定景别变化。
- 起终边界除了逐人姿态，还要写清本镜依赖的身体—物件—空间关系。关系在镜内不变时两端都保留；确需改变时，过程与终点必须有剧本依据。
- 冻结关键帧只写该瞬间能看见的内容；文字、手指、反射和遮挡要可生成。
- 近景类关键帧偏宽时，先核对画框要求与地点板的用途。写清画面边界和必要背景，检查是否同时要求完整空间入画。仍偏宽时可换同向局部视图，或在不丢失必要空间事实的前提下移除无关地点板，用样片对照验证，不一律删掉场景参考。
- 一集的关键帧要像同一部片：每条正文用同一句画风（写实就写写实，不混用「漫剧」「插画」这类会把一部分图拉向插画脸的词），每个场景写同一句光与色温；已有定调参考可复用；只有需要探索风格时才补代表帧，不为每场强制新增一轮生成与确认。
- 《视觉设定.md》的连续性锁在生效镜头上原样写进冻结关键帧正文；锁面不因“参考图会交代”而省略。
- 检查发现遗漏就直接修正文档，不生成覆盖表来证明自己检查过。镜头块里的「视觉依据」是本镜的依据字段，不属于额外覆盖表。

## 视觉依据与图片

镜头画面确定后，分别记录视觉事实来源、已有图片提示词项和真实参考文件。它们各自证明不同的事，不能用文字设定或 IMG 条目冒充图片。需要跨镜保持的可见人物、地点与道具都应有来源；只在画外发声、不可识别的局部不硬塞进画面清单。

参考按本镜职责选取，逐张说明用途、顺序、控制范围和不得控制的部分。手部特写不要求整套造型入画；维持道具状态也不意味着每镜都拍到道具。需要读脸、但全身板的脸不够清楚时，可按实际参考容量补同一造型的面部参考，不把补图变成每镜规定。

缺少持续物件或造型的设定条目时，保留已有证据和一致描述，交视觉设定阶段补充，不能伪造来源。实际图缺失时列计划；是否生成按本轮范围处理。当前参考模式和端口以实际部署为准，图片用途不等于锁帧能力。

已有 Toonflow 文档沿用原格式。使用五文档解析器时，视觉依据、画外声明、REF/PLAN、固定用途与标点统一按 [交接格式](../short-drama/references/creator-documents.md)；此处不重复维护语法。

## 修订

保留未受影响的镜头 ID。拆镜、并镜或改变镜头职责时，说明哪些下游视频提示词需要刷新，但不自动
重写用户没点名的文件。

## 完成

点名范围的原文都有镜头落实，每镜职责不重复、空间与状态连续、起止边界可制作、参考用途明确，
每镜「来源」解析到《剧本.md》的真实场景、剧本里每个场景都有镜头承载或已记入「未拍场次」，
且每镜描述里的可见人物、地点、道具都在本镜「视觉依据」里，即完成。画面需要、但《视觉设定.md》
还没有条目的可见物件，在末尾报告里逐项点名。本次请求同时修改
《图片提示词.md》与《分镜.md》时，当轮刷新受影响镜头的引用；不另建覆盖表。
视频提示词、生产和审查只有用户点名时开始。
写完本阶段文档后，可转 `$short-drama` 做局部机械核对（只核对已有文档）；五份齐备后再做完整核对。内容质量仍由创作者审查。
