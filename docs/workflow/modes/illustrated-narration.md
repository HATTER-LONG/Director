# 叙事动画制作：配音、插画与必要的动态镜头

本模式以讲述推进故事，按各段需要组合人物插画、背景、道具和动态镜头。旁白可以配无对白的动作、反应或环境视频，也可以配静图、局部分层动画或经检查的闭口循环；人物对白另选说话画面与声音来源。声音用途与画面形式分别决定，不按旁白比例规定静图比例。纯 TTS 插画作品可以不生成视频片段。

按下列步骤制作，直接复用所需技能与共用资料；不顺序加载标准流程的 01–06，不要求故事引擎、分集地图、整间房的空间资产或每镜视频提示词。已有剧本、配音和素材从当前步骤继续。技能的具体分工与条件组合统一见 [AGENTS](../../../AGENTS.md#制作文档入口)。

## 步骤与交付

| 步骤 | 做什么、交付什么 | 当前加载的技能 |
| --- | --- | --- |
| 1. 整理故事与声音脚本 | 保留主线、关键交锋与结尾；逐句标明说话人、旁白／当场对白／远程对白、画面信息；交付同一份制作脚本 | short-drama-write ＋ story-deslop ＋ natural-zh-writing。要先写文学故事稿才用 story-short-write 替代写作负责人；已有短篇只需分析时用 story-short-analyze |
| 2. 定画面方式与最小素材 | 给各段选静图、后期动画、闭口循环或表演视频；定角色外形、音色、背景色和必要道具，列素材缺口 | short-drama-storyboard ＋ short-drama-assets；有问答或动作的多镜序列再加 shot-sequencing |
| 3. 试配并完成 TTS | 先试正常语速、声线和易错词，再生成选定的旁白及人物配音；记录处理后文件与实测时长，回填对应段落预算 | 使用 Toonflow 音频节点时加载 toonflow；实际安装、构建或排障 ComfyUI 工作流才加 comfyui；语速与时间处理用 short-drama-edit |
| 4. 准备插画与构图 | 复用人物参考、配图、背景与道具；只补缺口，按实测声音安排构图切换与后期运动 | 资产图用 short-drama-image-prompts；本镜构图／关键帧用 short-drama-storyboard；实际出图加 toonflow。两类提示词不重复维护同一张图 |
| 5. 生成选定的动态片段（可跳过） | 为已选对白、无对白动作或循环准备提示词，按授权规格串行生成和验收，记录完整覆盖与可用区间；需要验证的新组合先选代表镜 | H3 文稿用 short-drama-video-prompts ＋ h3-prompt-writing；提交加 toonflow；验收用 continuity-checking，有相邻接镜加 shot-sequencing |
| 6. 按最终声音排时间线 | 合并 TTS、H3 原声和画面；生成并校对字幕时间，设计推近、分层运动、切换和必要文字；交付剪辑记录与可编辑工程 | short-drama-edit；采用 Remotion 时加环境中可用的 remotion-best-practices，按其入口在需要时读取创建、动画、字幕与渲染资料 |
| 7. 导出与回看 | 连播核对故事、说话人、语速、画面覆盖、字幕和切点；输出母版、需要的预览及实际验收记录 | short-drama-edit；另有专项审查请求时加载 short-drama-review |

每步只以当前需要的输入为前提。视觉素材可在配音前准备，最终镜长须等声音实测；需要从正式视频取静帧的配图，在步骤 5 后补齐。单卡运行时将 TTS 与 H3 分批安排，核实原任务结束并卸载模型后再切换，不交错加载每条任务。批次次序可以随现有素材调整，语速试配、实际定时和对白覆盖不能省略。

## 1. 声音脚本与对白覆盖

| 声音内容 | 默认承载方式 | 必须保留的边界 |
| --- | --- | --- |
| 叙述旁白、人物内心叙述 | TTS 配无对白动作／反应视频、插画、后期动画或闭口循环，按本段信息选择 | 说话人和声音用途明确；画中人物可以自然行动，不跟着旁白张嘴；后期旁白不写成 H3 要生成的对白 |
| 人物当场交谈 | 按本片选择使用 TTS 插画，或 H3 的说话画面与原声 | 逐句注明方式；同一问答不得为了省生成临时把某一句换成静图 TTS |
| 电话、手机语音、画外回复 | 仍按人物对白安排；可反打两端或保留剧本要求的画外声 | 不把“当前画框看不见说话人”误归为叙述旁白；电话两端不因切镜变成同一房间 |
| 必须看见的动作变化 | 后期动画能清楚交代的可用动画；需要身体表演与接触的用生成视频 | 写清起态、关键变化、终态；放大静图不能代替剧情动作 |

选择 H3 对话时，默认为问答双方准备可辨认的说话画面，按表演组织正反打或同框。创作者已要求全部人物对白有 H3 覆盖时，短回复和远程对白也逐句对应可用片段；可剪入倾听反应或声音桥，但不能用 TTS 顶掉缺失的说话素材。剧本明确保留的画外对白按其职责处理，不强制逐句特写。

叙事去味检查针对因果、详略和角色声口，保留有用的讲述语气、笑点和停顿。旁白承担的信息不必全部改成现场表演。涉及听见、看见与内心声时，只补读 [信息边界](../03-screenplay.md#感知与信息边界)。

## 2. 声画分镜与最小素材

沿用原镜号，在现有分镜表记录下列内容；画布表格、剪辑数据与 JSON 从同一来源同步：

| 字段 | 内容 |
| --- | --- |
| 镜号与声音 | 原文范围、说话人、逐字文本、声音类型与生成方式 |
| 画面任务 | 看谁、看见什么信息或变化、前后镜怎样接 |
| 素材与运动 | 静图／分层动画／闭口循环／H3；角色、道具、声音及参考版本；后期运动另列 |
| 时间 | 剪辑预算、生成目标和回收实测分开；待生成时不填虚构实测值 |
| 采用记录 | take、文件、可用区间、裁切／变速与待检项 |

一段旁白可以跨多张图，一个视频片段也可以剪出多镜；按信息、语气和动作转折划段。字数除以语速只作预算，不能把每段硬塞成固定秒数。总时长超出目标时，先删冗余或调整范围，保留合理停顿。

旁白讲准备过程时，画面可展示收拾、擦拭、装袋等完整小动作；讲判断变化时，可用倾听、犹豫、阅读或清点等反应与结果。每段先定画面要增加的信息，再选素材形式。需要看清的状态变化不能只靠缩放静图交代，也不为填满旁白把同一动作反复循环。无对白动作视频的原音是否保留另记，不能让原音中的临时说话覆盖已采用的旁白。

人物优先复用已选身份和造型，声音先查已有库。准备独立人物参考时必须先读 [人物参考规格与提交检查](../references/character-references.md)，按其默认规格或作品已确认的专用规格制作；本模式的“最小素材”不省略人物板的必要视图。简单背景用纯色、涂抹色或少量陈设，明确人物站位、朝向及桌面接触关系即可。只有某段确需连续走位、多机位地理或空间揭示，才为该段加载 scene-asset 和 [场景流程](../05-image-references.md#场景素材生成)，完成后返回本路线。

优先复用适合本段的插画或正式视频中的闭口帧，记录源 take 和原始时间。静帧只继承选中的构图与状态，不成为新的身份或空间权威。闭口呼吸循环需检查首尾衔接、脸部与嘴部稳定；不循环说话片段、不倒放口型。

## 3. 配音与定时

使用 [配音与时间对齐](../references/voice-and-timing.md) 的语速基准、发音复核与变速映射。先用短句、长句和易错词试配并回听，在最终速度下试剪旁白接对白，再批量生成。重生成、裁切或变速后回填实测时长，并更新后续画面和字幕。

TTS 的速度选择只作用于本次选定的配音段，可包含旁白和人物对白。H3 同步画音保留各自采用速度，不随 TTS 统一提速。具体 IndexTTS 入口与参数查 [当前部署](../references/local-model-capabilities.md#indextts-25本地参考音频配音)，不从界面名称推定请求值。已采用的配音只因已确认问题或用户新要求返工，不为统一生成方式重录。

## 4. 插画与构图生产

素材的版本、检查状态与画布分工按 [素材交接](../references/media-handoff.md)；实际生成按 [生产路由](../references/production-routing.md)。用户要求原画布承载全部成果时，在原画布分区复用。

用人物、简洁背景和必要道具完成本段构图，预留后期裁切与运动范围。资产参考图与成片配图按用途区分：本镜构图由分镜负责人维护，身份与造型板由资产提示词负责人维护。采用已有图片或视频抽帧时检查其状态和可用画幅，缺口才补图。

## 5. 必要的动态片段

只有选定的 H3 段落进入 [07 编译](../07-h3-prompts.md)、[08 生成](../08-toonflow-generation.md) 和 [09 验收](../09-video-review.md)，完成后回本页步骤 6。纯静图、后期缩放或分层动画不生成 H3 提示词。需要改变表演或摄影时加 h3-cinematic-director；参考、对白或声音异常加 minimax-h3-prompt-writer；节点与模型故障才加 minimax-h3／comfyui。

分辨率与是否试片按 [生成规格与可选试片](../08-toonflow-generation.md#生成规格与可选试片) 选择；用户已指定直接生成正式规格时，按该规格执行，不额外补低分辨率试片。普通单人对白仅绑定本段发声者声线；多人发声按实际模式分别绑定。无对白动作镜明确动作、环境声与后期配音分工，不需要绑定旁白声线。正式重生成后重新检查人物、说话人、完整字音、动作和切点。

干净画面、字幕与强调文字分开制作。选定后期排字时，表演提示词不写气泡、字幕内容或排版；必要限制按模型格式处理。对白近景用明确取景保证脸和口型可读，避免同时要求大脸与复杂手部操作。

## 6. 后期与字幕

画面随最终声音定时。静图可轻推近、局部裁切、分层位移或更换构图；运动服务本段信息，末端仍须看清人物和关键道具。问答可直接切，时间或场次变化再用有意义的转场，不为每张图添加特效。字幕、强调词和必要信息在后期排版，按竖屏安全区实看。

Remotion 是可选实现，沿用已有工程；未使用内置剪辑渲染器时，不把该渲染器的固定字段和字幕样式当成所有工程的要求。剪辑事实仍可从作品记录追溯。音乐、环境声和音效按本片设计，已指定纯人声就不自动铺底。

## 7. 导出、验收与交付

交付前逐句核对声音用途、说话人和覆盖方式，连播问答检查句首句尾、视线、持物、切点与口型。ASR 只辅助定位；没有实际听审或动态观看的项目如实标明。检查字幕原文、时间、安全区、实际片长、帧数、画幅、音轨、黑帧与完整解码；混音编码后测响度和真峰，不能把目标值当实测值。具体方法见 [剪辑技能](../../../.agents/skills/short-drama-edit/SKILL.md)。

超过画布容量时保留母版，另导出同剪辑、同字幕时间的预览并核对同步。技术完成、检查范围、未决问题和创作者采用分别记录。按授权释放空闲模型时，分别核实 ComfyUI 队列与独立 TTS 服务；电源状态遵从用户最新指令。经验按 [共用规则维护](../references/production-principles.md#经验如何进入共用规则) 归位，未经同条件测量不宣称固定节省比例。
