# story-deslop：故事与剧本去 AI 味

Director 适配版。先判断故事是否成立、笔墨是否放对地方，再修具体表达。方法来自上游，执行范围、文档职责与交接沿用 [Director](../../../AGENTS.md)。本技能可直接使用，不依赖 story-setup、专用 agent 或 hooks。

## 范围与文风

读取当前文本、作者要求和有关前文，按 [文风裁决](references/style-resolution.md) 沿用本作品的语言与信息边界。只处理本轮范围；明确只查词句或某段时，不扩成全篇重写。完整去味检查三层，每层都可以没有问题，不为交报告凑问题。

- 只要求检测、标注或审稿时，只交诊断，不改正文。
- 要求去味或润色时，直接修表达、已有承接和详略。新增事件、动机、证据、结果或揭露时机需要属于已授权的剧情修订范围；已有授权直接继续，缺少关键选择才提出具体问题。
- 保留人物口吻、情绪、伏笔和审美体验，不靠新增微动作、粗话、口误或冲突制造“真人感”。情绪直写、长句、排比、停顿和安静场景按实际功能判断。
- 剧本保留场号、说话人、动作／对白／VO／OS／画面文字边界。可拍摄动作的准确描述不能只因像“动作清单”就改成心理散文；也不把剧情所需对白概述成旁白。已确认台词仅在授权改写范围内修改，变化按 [变更传播](../../../docs/workflow/references/production-principles.md#来源改变后更新哪些地方) 同步下游。

## 按问题读方法

| 层 | 读取 | 检查对象 |
| --- | --- | --- |
| 表达 | [expression.md](references/expression.md) | 句段连贯、人物声口、套词和机械复现 |
| 用笔 | [narrative-focus.md](references/narrative-focus.md) | 场景重心、详略、关键交锋、细节和收尾 |
| 故事 | [story-logic.md](references/story-logic.md) | 行为依据、因果、他人立场、后果与知情顺序 |

完整去味读以上三份；定点处理按 [检查范围](references/deslop-gates.md) 只读相关方法。短篇有明确的强情绪或反转承诺时，加读 [短篇卖点保护](references/short-deslop.md)。[词表](references/banned-words.md) 只在定位具体表达时查，不作为删词清单。

## 诊断、修改与复核

1. 找出原文位置、阅读损失、已有依据和最小修法。区分可以直接修、仍需设计、资料不足；没有给全前文不等于故事没有铺垫。
2. 先处理有依据的因果与承接，再调整详略，最后修词句。改稿前沿用作品已有版本或备份方式保留可恢复原文；不在共享技能目录保存作品内容。
3. 剧本的剧情修改回 [short-drama-write](../short-drama-write/SKILL.md) 落进原剧本；短故事设计回 [story-short-write](../story-short-write/SKILL.md)。转交携带当前诊断和已有授权，不重复确认、不建立第二套事实。默认由当前执行者完成，不自动部署或调用专用子代理。
4. 对照改前版本，回读受影响的完整场景及相邻承接，核对事实、选择、空间、知情顺序、情绪和悬念。只为新发现的具体问题继续修改，不追求固定删减率或检测零命中。
5. 按需用 [natural-zh-writing](../natural-zh-writing/SKILL.md) 的对应条目检查残留句法、用词和冗余；它不再重做叙事诊断，也不抹掉刚保留的人物口吻与有效修辞。两者有冲突时，以作者要求、作品功能和已定事实裁决。

## 可选的确定性筛查

本地长稿、批量检查或用户要求检测时，可从本技能目录运行只读脚本，正文参数用绝对路径：

```sh
node scripts/check-ai-patterns.js --check --json --fail-on=blocking /绝对路径/正文.md
node scripts/check-degeneration.js --check --json --fail-on=blocking /绝对路径/正文.md
```

这两个脚本只报告，不改文件。退出 1 表示存在当前阈值下的命中，退出 2 表示命令或文件错误。脚本的 `blocking`、`mechanical` 等是上游分类，不自动成为 Director 的质量门槛；功能性纠错、人物声线、剧本标签和生产格式都要回到语境复核。零命中不证明叙事自然，也不能推断作者身份。

脚本按小说正文设计。剧本、分镜和提示词不整份套用小说格式阈值；必要时只扫描本次对白或旁白的临时副本，并保留原行位置，回源文判断。保留项在交付中说明即可，不为压数字创建白名单；已有明确作者偏好需要机器复扫时，白名单位置见文风裁决。

不默认执行会写回全文的 `normalize-punctuation.js`，不批量替换破折号、省略号、引号或分隔线。用户明确要求标点规范化时，先在副本查看变化，再按实际授权应用；小说格式建议不能改掉剧本标签、引用或模型语法。

## 交付与边界

简要说明三层中实际改了什么、保留了什么、仍缺什么依据；需要时附少量改前／改后对照。只在用户要求或作品已有流程需要时另存报告。脚本未运行就不声称检查通过，修改后按原任务交付全文或文件。

完整剧本与制作审查仍由 [short-drama-review](../short-drama-review/SKILL.md) 负责。此技能不生成媒体、不评价成片口型，也不把小说的字数、付费点或强情绪默认值变成短剧要求。
