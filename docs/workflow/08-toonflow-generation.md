# 08 Toonflow 视频生成

用户要求实际生成视频，且已有明确镜头、提示词和参考时，读本页。工作机地址及连接要求见 [AGENTS.md](../../AGENTS.md#项目目录与工作环境)。

## 使用 Skill

使用 [toonflow](../../.agents/skills/toonflow/SKILL.md) 操作工作机上的项目、画布和视频节点。需要排查本地工作流时按问题查 [minimax-h3](../../.agents/skills/minimax-h3/SKILL.md) 和 [comfyui](../../.agents/skills/comfyui/SKILL.md)。

入口、单任务或批次授权统一按 [生产路由与授权](references/production-routing.md)。本页说明节点操作与试片迭代。

## 素材交接与镜头画布

素材画布承载人物、环境、道具、界面和声音的生成、候选、选帧及返工历史。当前批次需要的素材通过相应用途检查后，再建立作品目录内的镜头生成画布；分镜和提示词文档可提前准备。

交接清单沿用作品现有素材记录，逐项给出资产标识、版本、实际路径、用途、检查结论、限制及已替代版本。尚未听审的声音或方位未核实的环境不当作已通过输入。先选定可用文件，再复制引用到镜头画布，避免连接仍会重生成的探索节点而令下游悄悄换图。

镜头画布只保留当前文件的图片/音频/视频载入节点、镜头或生成段、最终提示词、必要说明和有用连线。探索生成链、失败候选和旧素材留在素材画布与作品记录；镜头自己的 take 保持可追溯，但只将当前输入接入生成节点。素材更新时按清单替换引用，重查依赖镜头。

用户指定复用现有混合画布时，沿用该画布，将素材研发与当前镜头分区，标明历史和待验收项，断开废弃输入；不自动新建画布或删除历史文件。画布命名和整理服从本次范围。修改后回读实际文件、端口、连线、参考顺序、完整提示词和配置，确认未触发未授权生成。


## 操作

1. 确认服务和目标画布可用。调用 `getAppState` 取得当前 `connectionId`、`directory`、`canvasId`。切换项目或画布后重新读取。连接列表存在不等于页面能执行命令；再用一个实际画布读取确认。读取超时先恢复原连接与任务状态，不用新增节点或重投生成测试连接。
2. 按镜号定位实际节点。用 `getCanvasNodes` 查端口与数据，用 `getCanvasEdges` 查连接，用 `getNodeTools` 查节点支持的函数和参数。已有画布和打开的文档通过 MCP 修改。
3. 参照 [本地模型能力](references/local-model-capabilities.md)，核对节点实际使用的模式、预设、总时长、画幅、分辨率和声音选项。把当前提示词和真实参考连到正确端口。按实际入参核对挂图顺序、文件版本和正文标签。发现缺图或参数冲突时回到对应上游修正。

   新建节点从空白文生模式切到混合参考模式时，先接入参考，再调用配置函数选择参考模式。当前节点会按实际输入校验模式；没有参考时先设置混合模式会被拒绝。配置后回读模式、提示词及输入顺序，不把“节点已创建”当作制作准备完成。
4. 按用户授权的镜头和数量提交。需要先验证新模式时，用有代表性的镜头检查参考、动作和声音。同一次任务只提交一次；已批准批次内不重复询问。
5. 用节点提供的状态函数跟进。记录任务 ID。超时先查原任务、队列或已有输出，再决定是否补跑。看到任务完成后核对实际输出，读出文件位置、实际时长和音轨情况。

需要连续动作时，按 [接续规格](references/local-model-capabilities.md#两段视频怎么衔接) 核对挂入的片段与来源切点；不假定参考视频会带入音轨。停止和超时处理按 [恢复规则](references/local-model-capabilities.md#超时停止和恢复)，Toonflow 停止等待后仍须核实 ComfyUI 原任务状态。

## 用 0.4MP 快速调试

当前本地 H3 的提示词预览与调试优先用 **0.4MP**。这一做法用于缩短试片等待，尽快验证取景、空间、动作、对白与接镜。0.4MP 是总像素档位，实际宽高随画幅和节点取整变化，回收文件后登记。

1. **固定本轮要验证的内容。** 选当前问题所在镜头或代表性难镜头，记下预期起态、关键变化和终态。沿用目标画幅、模式、参考顺序与足够容纳动作对白的时长；有声音职责就保留声音生成。只为提速截掉后半段，会漏查动作终点和尾音。
2. **生成一版，检查一版。** 当前本地单卡按镜头串行提交，记录提示词版本、参考、实际参数、任务 ID 与 take。按 [视频验收](09-video-review.md) 先查镜头职责和状态，再查细节。这里的预览是导出的低分辨率试片，采样过程中显示的临时预览只用来定位明显问题。
3. **修订后对照。** 按 [共性问题排查](references/h3-prompt-diagnosis.md) 修改直接相关的描述或输入，回读节点核对后重跑。保留旧 take，用相同动作阶段比较，检查原问题是否解决、是否引入新偏差。叠加补丁已经互相冲突时先整理全文。
4. **通过后进入下一镜，并复查接镜。** 已授权的串行生成、检查与修订循环持续执行；任务范围和停止条件见 [生产路由](references/production-routing.md#单任务与有界批次)。单段通过后仍要对照相邻采用切点。
5. **按交付要求决定是否提高分辨率。** 预览通过后记录采用的提示词、参考与参数版本。已有片段满足交付就直接使用；需要更清晰的交付时，在授权规格内切换节点支持的分辨率。重新生成后复核身份、状态变化、关键动作、对白和接镜，再检查细节清晰度。升分辨率不会自动修好错误取景，重新生成也不保证复现预览表演。

排查阶段先看脸是否占有足够画幅，再判断纹理是否受分辨率影响。修改提示词同时更换分辨率时，记录整体结果，不将画面改善全归因于其中一项。

## 交付

回报镜号、take、任务 ID、实际预设和参数、参考顺序及可播放视频位置。任务尚在运行或取不到文件时，按当前证据报告状态和具体卡点。成功出片后转[视频验收](09-video-review.md)。
