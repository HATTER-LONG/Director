# 契约与所有权

## 工作流不是瀑布

```text
开发? -> 剧本 -> 视觉设定 -> 图片提示词
                    \-> 分镜 -> 视频提示词
                    \-> 授权范围内的媒体生产
```

可以从任一已有材料直接进入；Look Development 和审查都按需发生。各负责技能只修改自己的 Markdown，
引用上游可见事实，但不静默改写它们。

## 输出语言

| 内容 | 有项目配置时 | 独立任务默认 |
|---|---|---|
| 创作者可读说明与审查 | `short-drama.json#/language` | 用户当前语言 |
| 图片、关键帧的可复制正文 | `short-drama.json#/format/prompt_language` | `en` |
| 视频的可复制正文 | 目标视频模型档案的 `creator_authority.production_profile.choices.video_prompt_language`；未声明时回退 `format.prompt_language` | 根据目标视频模型确认；未声明时使用用户当前语言 |

创作者说明、通用提示词语言和视频模型提示词语言互相独立；画面中的对白和可读文字来自剧本/视觉事实，
不由描述语言推断。

## 稳定身份与引用

创作文档条目使用创作者可见的稳定 ID：`EP001-SC001`、`IMG-...`、`SHOT-...`、`MOTION-...`。其中 `IMG-...` 专属《图片提示词.md》的提示词标题，不代表已有图片。显示名可以改变，身份不因此改变。跨文档条目引用直接写这些 ID；不写哈希、内部路径、隐藏状态或第二套 record ID。

图片提示词、真实素材和挂图计划分别记录；精确的 IMG、REF、PLAN 语法只在 [交接格式](creator-documents.md) 维护。采用其他文档结构的项目保持同样的事实区分，不强制迁移字段。

## 规则分级

规则分级统一见 [规则与路由索引](knowhow-index.md#规则分级)。结构错误、语义义务、通常做法和表达选择分别判断，字数、镜头数与案例配方不作为通用结构门槛。

## 跨阶段连续性

| ID | 分级 | 要求 |
|---|---|---|
| CON-01 | structural_invariant | 相连镜头的终态与起态一致；需要改变时，由负责阶段明确修订。 |
| CON-02 | reviewed_invariant | 人物知情、伤势、持物归属、天气、光线和物理状态的变化有剧情依据。 |
| CON-03 | craft_default | 只交接影响下游的状态变化，不在每镜复制整份设定。 |
| CON-04 | structural_invariant | 状态变化写清前后状态、原因或来源场次、生效范围及受影响条目。 |
| CON-05 | taste_option | 已声明的蒙太奇、省略、梦境或主观画面可有意打破通常连续性。 |
| CON-06 | structural_invariant | 状态变化列出受影响的现有下游文档；尚未开展的阶段只说明后续要求，不预建空文件。 |
| CON-07 | structural_invariant | 使用五文档连续性锁时，在视觉设定声明准确原文及适用镜头、图片范围，生效范围内的关键帧和提示词原样携带；具体语法见交接格式。 |


## 信任与文件安全

只写文稿不自动提交媒体任务；查证资料按当前任务需要进行。生产入口、授权和恢复统一按 [生产路由与授权](../../../../docs/workflow/references/production-routing.md)。凭据由已配置的运行入口读取，不写进创作文档、提示词或交付包。文件路径留在必要的制作记录中，公开交付时按范围排除私有输入和内部运行信息。
