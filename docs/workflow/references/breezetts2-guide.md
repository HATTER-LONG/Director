# Breeze TTS 2 使用指南

2026-11-10 核对官方模型卡、官方仓库、已安装 `ComfyUI-Breeze-TTS-2` 的 `nodes.py/runtime.py` 和实时 `object_info`。Toonflow 已接入音色设计、固定参考配音、情绪配音和多角色固定参考对话；本页分别说明 Toonflow 与 ComfyUI 的操作。安装与运行参数见 [本地部署能力](local-model-capabilities.md#breeze-tts-2本地音色设计与多人配音)。

## 三种方式选哪种

| 目标 | 节点 | 输入 | CFG 起点 |
| --- | --- | --- | --- |
| 从描述创造一个新声音 | `BreezeTTS2VoiceDesign` | `instruction` 音色描述 + `text` 台词，不需要参考 | `4.0` |
| 用已有声音说新台词 | `BreezeTTS2VoiceClone` | 参考音频 + 其准确转写 + 新台词 | `1.0` |
| 保留声线，改变情绪或语速 | `BreezeTTS2VoiceDirection` | 参考音频 + 准确转写 + 表演指令 + 新台词 | `4.0` |

CFG 是指导强度，不是情绪强度百分比。高值也可能损伤自然度，先用节点推荐起点做对照。

## Toonflow：先试听音色，再固定参考对话

供应商为“本地 ComfyUI · Breeze TTS 2”，无需 API Key。如果当前页面仍显示旧模型列表，先刷新页面。音频节点的生成设置中可选以下四个模型：

| 模型 | 参考音频 | 主要参数 |
| --- | --- | --- |
| 角色音色设计与试听 | 不接参考 | 音色描述、CFG、种子；提示框填写试音台词 |
| 固定参考配音 | 一条 | 参考音频完整转写；提示框填写新台词 |
| 固定参考情绪配音 | 一条 | 参考转写、独立情绪与表达指令、CFG |
| 多角色固定参考对话 | 每角色一条，最多八条 | 角色数、每个角色的名字／参考转写／情绪／CFG、轮间静音 |

### 生成并固定角色声音

1. 新建音频生成节点，选择“角色音色设计与试听”。在“音色描述”中填写声音特征，提示框只放试音台词。
2. 生成后点击节点中的播放按钮试听。需要比较候选时修改种子；已选定的声音保存为独立 WAV。
3. 将满意的 WAV 下载后拖入普通音频节点，作为该角色的固定参考，再连接到对话节点。也可将已有工作区音频设为普通音频节点的输出。
4. 后续继续探索候选时，保留已选参考。直接把音色生成节点接入对话，会随该生成节点的输出变化；普通音频节点保存选定文件，便于固定版本。

接入演示画布名为 `BreezeTTS2-音色试听与固定参考对话`，包含四个可重新生成的试音节点、四个已固定的参考节点、四角色十三轮对话，以及单人参考／情绪配音示例。演示参考复制到各自普通音频节点的独立目录，复制内容与原候选一致；后续生成新候选不会自动替换它们。

### 每个角色单独设置情绪

选择“多角色固定参考对话”，按角色顺序连接参考，设置匹配的角色数量。参考序号只计音频：第一条音频对应角色 1，第二条对应角色 2，以此类推。调整参考顺序后，同时核对角色参数。

每位角色分别填写：

- **角色名**：与脚本的 `speaker` 或“名字: 台词”对应，不能重复。
- **参考音频完整转写**：对应这条参考的全部实际发声，不能填本次新台词。
- **独立情绪与表达**：例如一位角色写“紧张警觉，压低音量”，另一位写“沉着，有些疲惫”。各角色分别传给自己的 Speaker，不共用一个全局情绪。
- **情绪指令 CFG**：有情绪描述时使用该数值，默认 `4.0`；情绪留空时使用参考克隆基线 `1.0`。它控制指令指导，不是精确的情绪强度。

角色的情绪设置对该角色全部轮次生效。要让同一人逐句切换情绪，应复用同一参考分段合成；这里不把 JSON 的单轮 `emotion` 当成已接通的功能。

提示框支持两种写法：

```text
林岚: 先别开门。
阿卓: [咳嗽] 你听见什么了？
林岚: 门外有人。
```

或粘贴仅含 `speaker/text` 的 JSON 数组。Toonflow 适配器会在上传与排队前检查参考数量、角色名和脚本对应关系；JSON 的额外控制键会明确报错，情绪应填入角色参数。当前适配器使用这两种规范格式，ComfyUI 插件额外支持的别名和 Markdown 人名写法不作为 Toonflow 的输入约定。

### 输出和任务恢复

Toonflow 当前输出支持 WAV／MP3，默认 `24000 Hz`；界面中的 PCM、Opus 不在此适配器的输出范围，选择后会明确提示。ComfyUI 原始 WAV 另行保留，Toonflow 在任务对应的素材目录回收导出文件。

适配器保存原请求标识和 ComfyUI prompt_id，恢复时查询原任务，不重新合成参考或重复排队。已实际验证生成后刷新页面、重新打开演示画布并回收同一个任务的输出。停止 Toonflow 等待后，ComfyUI 任务仍可能运行；按 [生产恢复原则](production-routing.md#小规模验证与恢复) 先查原任务。

本次四角色十三轮及单人两种模式均完成实际生成，参数与产物见 [Toonflow 接入记录](../../reviews/2026-11-10-breeze-toonflow-integration.md)。可导入供应商源码为 [comfyBreezeTts2.ts](../../../integrations/toonflow/comfyBreezeTts2.ts)，音频节点的配套改动见 [补丁](../../../integrations/toonflow/audioGenerationBreeze.patch)。

## 音色设计与试听

在 ComfyUI 的 Workflows 侧栏打开 `音频处理/配音/BreezeTTS2-BF16-音色设计与试听`；刷新侧栏可看到新文件。可导入的仓库副本见 [音色设计工作流](../../examples/comfyui/BreezeTTS2-BF16-音色设计与试听.json)。

1. 在 Voice Design 的 `instruction` 中写声线身份、音色与说话方式，在 `text` 中写测试台词。
2. 保持 CFG `4.0`，点击运行。右侧 `Preview Audio` 与保存 WAV 节点均可播放；保存节点同时写入音频文件。
3. 改 seed 探索新候选；对照同一候选的表现时固定正 seed 与其他参数。
4. 满意后保存该 WAV，后续作为 Voice Clone／Direction 的参考音频，填写它实际读出的完整转写。每次重新用同一句音色描述设计，声线仍可能改变。

示例：

```text
instruction：三十岁左右的女性，中低音，音色温暖清楚，略带沙哑；普通话，像深夜电台主持人一样亲切从容，用自然语速说话。
text：晚上好，欢迎来到深夜电台。窗外还在下雨，回家的路上，记得慢一点。
```

中文台词配中文指令，英文台词配英文指令，是官方建议。先写几个有区分度的声音特征；互相冲突的要求，如同时“轻声耳语、响亮喊叫”，应拆成不同候选或片段。生成的是一段符合描述的候选声音；需要复刻某个已有具体音色时使用参考克隆。

## 情绪支持哪些

Breeze 的情绪控制使用自然语言，官方没有给出封闭的“全部情绪枚举”。可描述开心、悲伤、愤怒、紧张、恐惧、惊讶、厌烦、释然等，以及轻声、耳语、激动、缓慢等表达方式；这些是可尝试的指令，效果需要样本对照，不能逐项当成已经实测的开关。

| 想要的效果 | `instruction` 示例 | 建议 |
| --- | --- | --- |
| 压着怒气 | 克制地生气，压低音量，咬字清楚，语速稍慢 | 保持声线参考不变 |
| 放下心来 | 带着疲惫和释然，轻声说话，句子之间自然停顿 | 适合短句对照 |
| 紧张警觉 | 紧张而警觉，音量较低，稍快，但每个字说清楚 | 同时回听漏字与截尾 |
| 亲切开心 | 语气轻快、亲切，笑意自然 | 笑意与实际发笑事件分开控制 |

Voice Clone 节点没有 `instruction`。把表演说明写在它的 `reference_text` 中会破坏参考转写；正文中的 `[愤怒]` 也不是已确认的标准情绪标签。要保留声线再改变表演，打开 [参考声线情绪控制工作流](../../examples/comfyui/BreezeTTS2-BF16-参考声线情绪控制.json)，使用 Voice Direction。

参考不宜有背景音乐、多人交叠、明显混响或长静音。准确转写覆盖全部实际发声，音频中重复的词也要保留；不能填新台词代替参考转写。Speaker 节点的空转写可自动调用 Whisper，但结果仍需核对，且可能产生额外模型加载；示例设计声线不需要识别，所以关闭了自动转写。

Voice Direction 的 `stitch_reference=none` 仅返回新台词；`before/after` 会在输出前后拼接原参考音频。这是输出编辑，不增加克隆或情绪控制能力。

## 已确认的声音事件标签

事件直接放在正文要发声的位置：

| 声音事件 | 中文正文 | 英文正文 |
| --- | --- | --- |
| 笑 | `[笑]` | `(laugh)` |
| 咳嗽 | `[咳嗽]` | `(cough)` |
| 清嗓子 | `[清嗓子]` | `(clears throat)` |
| 叹气 | `[叹气]` | `(sigh)` |

```text
[叹气] 你能回来，我就放心了。
这件事……[清嗓子] 我还是当面说吧。
```

这四组是官方与当前节点明确列出的用法，不是对模型所有可能发声的穷举。别名和其他反应词可能产生声音，也可能被朗读、忽略或影响台词；未经对照不登记为支持能力。不要把英文事件改成 `[laugh]`，或把中文事件改成 `(笑)` 当成推荐写法。标签不应出现在字幕成稿中。

## 停顿、语速和多音字

| 需求 | 做法 | 当前边界 |
| --- | --- | --- |
| 自然停顿 | 按句意用标点，必要时用 instruction 要求从容、短暂停顿 | 不承诺某个标点等于固定毫秒 |
| 多人各轮之间的静音 | `pause_between_speakers`，范围 `0–3` 秒，步长 `0.05` | 实际在每两个脚本条目间插静音，同一角色连续两条也适用；不含片段原有首尾空白 |
| 指定某一处停 `0.5` 秒 | 在完整语义边界拆段，后期插入静音 | 当前没有已确认的 `[pause=500ms]` 或 SSML `<break>` 入口 |
| 整体快慢 | Voice Direction 用自然语言描述；需要精确播放倍率时在后期保音高变速 | 没有 IndexTTS 的 `duration_factor` 参数 |
| 多音字、专名 | 先用足够明确的上下文短句对照；必要时准备同音替代表达，另存实际合成输入 | 当前官方接口与节点未提供已确认的拼音／音素强制控制；不套用 `<行\|HANG2>` |

多音字短句对照可用“他去银行办业务”“沿着河边步行回家”，先确认模型是否真的误读。需要改写或同音替换时，字幕保留已确认原文；若替换会改变剧情、名称含义或对白，按原稿修订权限处理，不能只为识别分数改稿。拼音、声调数字、括号注音都可能被直接念出，不当成已支持格式。

## 多人对话的真实控制方式

ComfyUI 插件提供 `BreezeTTS2Speaker → BreezeTTS2MultiSpeaker`，最多八个角色，可混合设计与克隆声线。它是插件按角色逐轮调用模型、再顺序拼接的实现，不是模型一次推理自动完成多人交叠表演。

每个 Speaker 的用法：

- `audio=none`、填写 `instruction`：设计音色，CFG 约 `4`。
- 选参考文件或连接 `reference_audio`、准确 `reference_text`、空 instruction：克隆，CFG 约 `1`；接线音频会覆盖文件下拉选择。
- 使用参考音频与转写，再填 instruction：对这个声线施加表演指令，CFG 约 `4`。

脚本用 ASCII 冒号，也可用 JSON：

```text
林岚: 先别开门。
阿卓: [咳嗽] 你听见什么了？
```

```json
[
  {"speaker": "林岚", "text": "先别开门。"},
  {"speaker": "阿卓", "text": "[咳嗽] 你听见什么了？"}
]
```

节点会预先检查角色名。纯文本没有角色名的新行会并入上一轮；想明确新增一轮就再次写名字。JSON 推荐只用 `speaker/text`；解析器会忽略额外 `emotion/instruction/pause` 键，它们不能控制单轮。不要往脚本正文插无角色名的导演说明。

当前 Speaker 的 instruction 对该角色全部轮次生效。若同一角色前一句愤怒、后一句释然，需要拆段用同一参考分别调用 Voice Direction，再拼接。也可建立共用同一参考的表演变体，但不同 Speaker 槽位会增加不同 seed 偏移，必须回听身份一致性。

固定正 seed 时，多人节点按槽位加偏移，而非每轮换种子；移动角色槽位会改变有效种子。相同描述与种子也不保证长对话声线完全不漂移，正式角色优先固定一条参考音频。真正的抢话、同时说话需要各自生成后分轨混音。

## 固定参考的四角色、多轮对话

需要保持人物声线时，打开 `音频处理/配音/BreezeTTS2-BF16-四角色固定参考-多轮对话`，或导入 [固定参考工作流](../../examples/comfyui/BreezeTTS2-BF16-四角色固定参考-多轮对话.json)。本地已接好四份参考，沿用旁白、林岚、阿卓、老周的十三轮脚本。图中每个角色都有独立的 `Load Audio → Speaker.reference_audio` 连线，再接到 Multi-Speaker 的对应槽位。

1. 日常生成只改 Multi-Speaker 的台词，保留角色参考文件与槽位。
2. 更换声线时，在该角色的 Load Audio 选择或上传新 WAV，同时更新 Speaker 的 `reference_text`，使其对应参考中的全部实际发声。当前先用 `instruction` 留空、CFG `1.0` 的参考克隆基线，关闭自动转写。
3. Speaker 的 `audio` 下拉框显示 `none` 时，已连接的 `reference_audio` 仍会优先生效；是否走克隆要看真实接线，不能只看下拉框。
4. 增加角色时，复制一组 Load Audio 与 Speaker，接到空闲的 `speaker_5…8`，保持名字唯一并同步脚本。这里的多参考是每个角色一路，单个 Speaker 没有多条独立参考输入。

配套的 [四角色参考音色库工作流](../../examples/comfyui/BreezeTTS2-BF16-四角色参考音色库-生成与试听.json) 用于为每个角色生成并试听参考候选。先选定 WAV，再把它接到对话图；之后重新设计候选时，对话图仍使用已选文件，需手动替换才会改变声线。参考来源、种子、生成输入与实际文件见 [参考清单](../../examples/comfyui/breeze-fixed-speaker-references.json)。导入其他机器时需重新上传这些参考，或换成自己的素材。

Speaker 本身准备角色配置，不会预先生成一条可持久复用的设计音色；`audio=none` 且未接参考时，实际在后续每轮合成中走设计路径。当前安装版本的 Speaker 有 `speaker/audio/transcript` 三个输出：有参考时 `audio` 输出参考本身，无参考时是占位静音，不能当成新设计的声音。固定参考版的对话图不含 Voice Design 节点，各轮直接使用同一角色参考；实际声线稳定性仍需听审。

## 四角色、十三轮的无参考设计例子

打开 `音频处理/配音/BreezeTTS2-BF16-四角色悬疑对话`，仓库副本与 [完整 JSON 脚本](../../examples/comfyui/breeze-four-speaker-dialogue.json) 可直接使用。角色为旁白、警觉克制的林岚、紧张逞强的阿卓、沉着疲惫的老周，包含四种声音事件、不同说话节奏和统一轮间静音。

四个 Speaker 的 instruction、脚本与保存／试听节点均已配置；默认先用描述设计音色，无需另外上传四段参考。制作中可逐个改为参考克隆。脚本中的旁白同样是一名说话人，动作描述不自动转为音效；示例没有生成门把手声、铃声等独立音效。

示例起始三轮：

```json
[
  {"speaker": "旁白", "text": "电台下播后，走廊忽然停了电。值班室的门外，有人在慢慢转动把手。"},
  {"speaker": "林岚", "text": "阿卓，先别开门。老周，你不是说楼里没人了吗？"},
  {"speaker": "老周", "text": "[清嗓子] 我锁的是大门。后面那条楼梯，今天有人检修。"}
]
```

`max_new_tokens` 是每轮最多生成多少音频帧，不是整个对话时长；提高它也不强制模型说得更久。先试有代表性的短轮次，检查换人、参考转写、事件是否被念出及句尾，再运行整段。最终时长以输出音频为准。
